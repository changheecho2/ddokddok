# 운영 런북 (Runbook)

실무에서 반복되는 작업(새 기수 전환, 자동갱신 설정 등)을 다음 사람이 바로 따라할 수 있게 정리한 문서.

> 모든 DB 작업은 CLAUDE.md 규칙대로 **Python supabase 클라이언트**로만 한다 (터미널 직접 SQL 금지 — 한글 깨짐).
> 스크립트 실행 전 `backend/.env`에 값이 채워져 있어야 하고, venv가 필요하다.

---

## 배포 / 인프라 정보

| 구분 | 값 |
|------|-----|
| 백엔드 (Render) | `https://ddokddok-backend.onrender.com` |
| 프론트 | GitHub Pages (`npm run deploy` → gh-pages 브랜치) |
| 프론트 프로덕션 API URL | `frontend/.env.production`의 `VITE_API_BASE_URL` (gitignore — 추적 안 됨) |

외부 스케줄러:
- **cron-job.org** — 디스코드 알림(`POST /notify/check`), 자동갱신(`POST /refresh`)
- **UptimeRobot** — Render 콜드스타트 방지용 5분 핑 (무료티어는 GET만 가능)

## 자동갱신 (하루 1회 + 수동)

`POST /refresh`를 cron-job.org에서 **하루 1회(00:05 KST)** 호출하고, 나머지는 필요할 때 **수동 새로고침**으로 채운다. 실시간성은 일지 작성 기간에만 의미 있으므로 저빈도로 충분하다. **코드 변경 없음.**

> ⚠️ **왜 저빈도인가 — 밴드 API 일일 쿼터**
> refresh 1회 = 포스트 목록 1회 + **글마다 댓글 조회**(활성 일지 글 수만큼). #9월목표설정 25글이면 1회에 약 26회, 일지가 쌓이면 1월엔 ~126회까지 늘어난다.
> 과거 `*/10`(10분 주기)로 돌렸다가 하루 ~3,700회로 **밴드 앱 쿼터를 초과**(`result_code 1001, "App quota has been exceeded"`)해, 모든 밴드 호출이 막히고 새로고침이 0건 → **전 멤버가 X로 뜨는 장애**가 났다. 반드시 저빈도로 유지할 것.

### cron-job.org job 설정값

| 항목 | 값 |
|------|-----|
| URL | `https://ddokddok-backend.onrender.com/refresh` |
| **Request method** | **POST** ← ADVANCED 탭에서 반드시 지정 |
| 스케줄 | 하루 1회 `5 0 * * *` (timezone **Asia/Seoul**, 00:05 KST) |
| 인증/헤더/바디 | 불필요 |

- 00:05 실행은 전날 마감(check_date 다음날 KST)을 반영한 뒤, 00:10 결과 알림이 최신 데이터를 읽게 하는 순서라 이상적이다.
- 일지/댓글 마감 기간엔 관리자 화면에서 수동 새로고침(쿨다운 1분)으로 수시 갱신.

### 함정 & 참고
- ⚠️ cron-job.org 기본 메서드는 **GET**. POST로 안 바꾸면 `/refresh`가 **405 Method Not Allowed**. (ADVANCED 탭 → Request method → POST)
- `POST /refresh`는 매번 `deposit_history` 전삭제 후 자동 규칙으로 **재계산**(멱등). 수기 입력(모임 출석 `meeting_attendance`, 조모임 `members.small_group_satisfied`)은 별도 테이블이라 **안 지워짐**.
- 쿨다운 1분(`refresh.py`의 `COOLDOWN_MINUTES`). 수동 연타 시 `?force=true`로 쿨다운 무시 가능.
- 동작 확인: `GET /refresh/status`의 `last_refresh_at`이 방금 시각으로 갱신됐는지 본다.
- job이 **Enabled** 상태인지 확인 (테스트만 성공하고 비활성이면 자동으로 안 돎).

## 새 기수 전환 절차

새 기수가 시작되면 (1) 밴드 키 교체 → (2) 전 기수 데이터 백업·초기화 → (3) 새 멤버/일지/모임 등록 → (4) 매칭 검증 순으로 한다.

### 1. 새 밴드 키 찾기

토큰으로 접근 가능한 밴드 목록을 조회해 `band_key`를 찾는다.

```bash
cd backend
TOKEN=$(grep '^BAND_ACCESS_TOKEN=' .env | cut -d= -f2)
curl -s "https://openapi.band.us/v2.1/bands?access_token=${TOKEN}"
# → 응답의 bands[].name / band_key 에서 새 기수 밴드 선택
```

찾은 키로 두 곳을 바꾼다:
- 로컬: `backend/.env`의 `BAND_KEY`
- **프로덕션: Render 대시보드 → 백엔드 서비스 → Environment → `BAND_KEY` 변경 후 재배포** (이걸 안 하면 라이브에 반영 안 됨)

### 2. 새 멤버 명단 가져오기

밴드 멤버 API로 로스터를 뽑는다. **이름이 밴드 작성자명(`author.name`)과 정확히 일치**해야 매칭된다.

```bash
KEY=$(grep '^BAND_KEY=' .env | cut -d= -f2)
curl -s "https://openapi.band.us/v2.1/band/members?access_token=${TOKEN}&band_key=${KEY}"
# → result_data.members[].name
```

### 3. 백업 → 초기화 → 시딩 스크립트

아래 스크립트를 `backend/`에 저장하고 `./venv/Scripts/python.exe <파일>`로 실행한다.
`NEW_MEMBERS`, `JOURNALS`, `MEETINGS`만 이번 기수에 맞게 고치면 된다.

```python
# backend/_reset_cohort.py  (실행 후 삭제 권장)
import sys, io, json
from datetime import datetime
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")
from app.database import supabase

# ── 이번 기수 값만 수정 ───────────────────────────────
NEW_MEMBERS = ["홍정민", "조창희", "..."]  # 밴드 로스터 순서
JOURNALS = [
    # (해시태그, 라벨, 일지마감 check_date, 댓글마감 comment_check_date)
    ("#9월목표설정", "9월 목표설정",             "2026-09-06", "2026-09-13"),
    ("#9월목표달성", "9월 달성 + 10월 목표설정", "2026-10-04", "2026-10-11"),
    # ... 이후 매월 "#N월목표달성" (전달 달성 규칙)
]
MEETINGS = ["2026-09-19", "2026-10-31", "2026-12-05", "2027-01-09"]
# ──────────────────────────────────────────────────

TABLES = ["members", "journals", "meetings", "journal_checks", "comment_checks",
          "meeting_attendance", "small_group_attendance", "deposit_history"]
IMPOSSIBLE = "00000000-0000-0000-0000-000000000000"

# 1) 백업
backup = {t: supabase.table(t).select("*").execute().data for t in TABLES}
stamp = datetime.now().strftime("%Y%m%d_%H%M%S")
with open(f"backup_{stamp}.json", "w", encoding="utf-8") as f:
    json.dump(backup, f, ensure_ascii=False, indent=2)
print("[백업]", {t: len(v) for t, v in backup.items()})

# 2) 초기화 (자식 → 부모 순서)
for t in ["journal_checks", "comment_checks", "meeting_attendance",
          "small_group_attendance", "deposit_history", "journals", "meetings", "members"]:
    supabase.table(t).delete().neq("id", IMPOSSIBLE).execute()

# 3) 시딩
supabase.table("members").insert([{"name": n} for n in NEW_MEMBERS]).execute()
supabase.table("journals").insert(
    [{"hashtag": h, "label": l, "check_date": c, "comment_check_date": cc}
     for h, l, c, cc in JOURNALS]).execute()
supabase.table("meetings").insert(
    [{"meeting_date": d, "sequence": i} for i, d in enumerate(MEETINGS, 1)]).execute()
print("[완료] members/journals/meetings 시딩")
```

> `members` 신규 삽입 시 `deposit_balance`는 기본값 50000, `small_group_satisfied`는 NULL(미입력=차감없음)로 들어간다.
> 백업 JSON은 `.gitignore`의 `backend/backup_*.json`으로 커밋 제외됨 (멤버 개인정보 포함).

### 4. 매칭 검증 (필수)

신규 멤버 이름이 밴드 작성자명과 안 맞으면 전원 미작성으로 뜬다. 첫 일지 해시태그로 검증한다.

```python
# backend/_verify_match.py  (읽기 전용, 실행 후 삭제 권장)
import sys, io, os, asyncio
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")
import httpx
from app.database import supabase

HASHTAG = "#9월목표설정"  # 이번 기수 첫 일지
TOKEN, KEY = os.getenv("BAND_ACCESS_TOKEN"), os.getenv("BAND_KEY")
members = {m["name"] for m in supabase.table("members").select("name").execute().data}

async def main():
    authors, params = set(), {"access_token": TOKEN, "band_key": KEY, "locale": "ko_KR"}
    async with httpx.AsyncClient(timeout=30) as c:
        while True:
            rd = (await c.get("https://openapi.band.us/v2/band/posts", params=params)).json()["result_data"]
            for p in rd.get("items", []):
                if HASHTAG in (p.get("content") or ""):
                    authors.add(p["author"]["name"])
            nxt = rd.get("paging", {}).get("next_params")
            if not nxt: break
            params["after"] = nxt["after"] if isinstance(nxt, dict) else nxt
    print("작성했지만 멤버DB에 없는 이름(=오타 의심):", sorted(authors - members) or "없음")
    print("멤버 중 미작성:", sorted(members - authors))

asyncio.run(main())
```

"멤버DB에 없는 이름"이 나오면 그 사람은 `members` 이름 오타로 매칭 실패 중 → `members.name` 수정.
